# Pingoose — GNOME 42 평가 예약 알림

**현재 인트라 v3의 Pending evaluations와 같은 서비스**를 조회합니다.
전용 WebKit 창으로 로그인하고, 이후 평가 GET 요청만 10초 간격으로 보냅니다.
내가 평가자인 새 평가 ID가 나타나면 GNOME 배너·최근 5개 카드·화면 테두리 점멸로 알립니다.
일반 브라우저를 켜 둘 필요가 없습니다. 창을 닫으면 숨겨지고, 확장을 끄면 보조 프로세스도 종료됩니다.

## 설치 / 테스트

GNOME Shell **42**, GJS, GTK 3, WebKit2 **4.0**, libsoup **2.4** 바인딩을 사용합니다.
Ubuntu 22.04 / GNOME 42.9 / X11 환경에서 개발했습니다. Node.js와 Python 3은 회귀 검사·별도 API 진단에 사용합니다.
현재 OS 사용자 이름과 42 로그인명이 같아야 합니다.

```sh
cd ~/pingoose
./check.sh
./install.sh
```

1. **업데이트 적용:** X11에서 `Alt+F2` → `r` → Enter. 또는 로그아웃/로그인합니다.
   설치 스크립트는 데스크톱을 재시작하지 않습니다. 단순히 확장을 껐다 켜면 옛 JavaScript가 캐시되어 남을 수 있습니다.
2. 필요하면 `gnome-extensions enable pingoose@local`로 활성화합니다.
3. 메뉴의 **인트라 창 열기**에서 로그인합니다. 기존 전용 프로필의 로그인이 유효하면 자동 연결됩니다.
   로그인 뒤 창을 닫거나 **인트라 창 숨기기**를 누릅니다. 일반 브라우저의 세션을 복사하지 않습니다.
4. **「인트라 v3 · 10초마다 평가 조회 중 · 로그인명 · 대기 N건 · 최근 시각」**을 확인합니다.
   이 문구의 `v3`로 새 버전 적용 여부를 구분할 수 있습니다. 대기 건수는 내가 평가자인 항목만 셉니다.
5. **테스트 알림 보내기**는 배너·카드·점멸 경로를 시험합니다. 실제 예약이나 기준 목록은 바꾸지 않습니다.
6. 위 조회 상태가 표시된 **이후** 내 슬롯에 실제 새 예약을 만들어 수신을 확인합니다.
   첫 번째 성공한 목록은 조용히 기준으로 저장하므로, 처음부터 있던 평가가 바로 울리지는 않습니다.

**현재 실제 예약 수신까지 검증됐다는 뜻은 아닙니다.** 인증된 실제 서비스 조회는 성공했지만,
확인 시점에는 대기 평가가 0건이었습니다. 예약이 있는 화면과 알림을 함께 확인하는 마지막 실험은 남아 있습니다.

## 데이터 경로 / 인증

기존의 `api.intra.42.fr/v2/.../scale_teams`는 현재 인트라 화면이 사용하는 경로와 달랐습니다.
현재 경로는 실제 배포 프런트엔드에서 확인했습니다. 조사 근거는 `API-FINDINGS.md`를 참고하세요.

```http
GET https://intrapy.intra.42.fr/api/v1/users/me/scale_teams
```

- 전용 웹뷰가 정상적인 인트라 로그인 절차를 수행합니다. localhost OAuth 콜백이나 기존 앱 UID/secret을 사용하지 않습니다.
- 웹뷰가 같은 서비스의 **본인 요약/평가 GET에 사용한 Bearer 인증**만 보조 프로세스 메모리에서 재사용합니다.
  평가 위젯을 숨겨 놓아도 본인 요약 요청으로 인증을 연결할 수 있습니다.
  다른 목적지로 보내거나 로그·상태 파일·패키지에 기록하지 않습니다.
- 발급자와 로그인명으로 계정 선택을 확인합니다. JWT의 실제 인증·서명 검증은 HTTPS API 서버가 수행합니다.
- 조회 목적지는 위 HTTPS URL로 고정하며 TLS 검증을 끄지 않고 리디렉션도 따라가지 않습니다.
- 평가 생성·취소·수정 요청은 보내지 않습니다. 코드가 버튼을 자동으로 클릭하지도 않습니다.
- 정상 조회가 끝난 뒤 10초 후 다음 요청을 보냅니다. 화면 전체를 매번 새로고침하지 않습니다.
- 인증이 만료되면 숨긴 웹뷰에서 정상 로그인 흐름을 다시 시도합니다. 보이는 창이나 로그인 폼을 주기적으로 새로고침하지 않습니다.
  로그인이 다시 필요하면 메뉴에서 창을 열어 직접 진행합니다.
- 네트워크·응답·권한 오류를 빈 목록으로 처리하지 않습니다. 재시도 간격은 20~300초이며 더 긴 `Retry-After`도 존중합니다.
  한 번에 요청 하나만 보내고, 응답은 1MB·1,000개 항목으로 제한합니다.

웹뷰 프로필은 `${XDG_DATA_HOME:-~/.local/share}/pingoose/`를 사용하며 상위 디렉터리는 **700**입니다.
사이트가 관리하는 쿠키·로그인 저장소에는 인증 정보가 남을 수 있으므로 이 폴더도 공유하면 안 됩니다.
다른 브라우저의 쿠키나 비밀번호는 읽거나 복사하지 않습니다. 기존 전용 프로필은 재사용하며 삭제하지 않습니다.

## 기준 목록 / UI

- ID는 `${XDG_STATE_HOME:-~/.local/state}/pingoose/intrapy-evaluations.json`에 원자적으로 교체 저장합니다.
  파일은 **600**, 디렉터리는 **700**입니다. 계정 식별자와 최근 최대 2,000개 ID만 저장합니다.
- 첫 목록은 무음입니다. 이후 새 ID만 알리며, 재시작·삭제 후 재등장으로 이미 기억한 ID가 다시 울리지 않습니다.
- 손상되거나 권한이 맞지 않는 상태 파일은 덮어쓰지 않고 오류를 표시합니다.
  이전 API 버전의 `evaluations.json`은 읽거나 변경하지 않습니다.
- 카드에는 시작 시각(PC 로컬 시간), 제공된 프로젝트명, 평가 ID를 표시합니다. 카드 이력은 메모리에만 있습니다.
- 배너에는 평가 상세 정보를 넣지 않습니다. 상세는 패널 팝오버에서 확인합니다.
- **화면 점멸**은 끄기 또는 1~5회, 기본 1회입니다. 기존 GSettings 설정을 유지합니다.
- 모든 모니터에 클릭을 가로채지 않는 민트색 테두리를 약 0.9초 표시하며, 점멸 시작 간격은 최소 3초입니다.
  알림이 몰려도 진행 중 효과를 겹치거나 연장하지 않습니다.
- 방해 금지·애니메이션 끄기·화면 잠금에서는 점멸하지 않습니다. 방해 금지에서도 카드는 추가합니다.
- **알림 카드 지우기**는 저장된 ID를 초기화하지 않습니다.
- 세션 D-Bus 이름으로 보조 프로세스 중복 실행을 막습니다. 확장 종료·stdin EOF·SIGTERM 시 HTTP와 웹뷰를 함께 종료합니다.
  서로 다른 로그인 세션·PC가 같은 프로필/상태 파일을 공유하는 구성은 지원하지 않습니다.

```sh
gnome-extensions disable pingoose@local
```

## 캠퍼스 최근 평가 조회 — 별도 스크립트

```sh
cd ~/pingoose
python3 -B campus_evaluations.py             # 최근 10건
python3 -B campus_evaluations.py --limit 20  # 1~100건
```

현재 OS 로그인과 같은 42 계정의 **주 캠퍼스**를 자동으로 찾습니다. 현재 `sanghul2`의 주 캠퍼스는 경산(`69`)입니다.
기존 개인 설정의 UID/secret으로 앱 토큰을 발급받아 다음 경로를 **한 번만** 조회합니다.

```http
GET /v2/scale_teams?filter[campus_id]={campus_id}&sort=-begin_at&page[size]={limit}&page[number]=1
```

- **시작 시각 내림차순**이며 `future`/`filled` 필터를 넣지 않습니다. API에 노출된 미래 항목이 있다면 함께 포함될 수 있습니다.
- JSON으로 평가 ID, **평가자(`corrector`)·피평가자 목록(`correcteds`)의 인트라 로그인명**, 시작·생성·평가표 작성 시각, 프로젝트 ID와 평가자 ID를 출력합니다.
- 시간은 PC의 로컬 시간대와 UTC 오프셋을 함께 표시합니다. `count`는 이번 응답 건수이지 캠퍼스 전체 평가 수가 아닙니다.
- 이름이 API에서 비공개이거나 제공되지 않으면 `null`로 표시합니다. 피평가자가 여러 명이면 모두 나열합니다.
- 이메일·평가 코멘트·점수·토큰은 출력하지 않습니다. 전체 원본 응답을 덤프하지 않습니다.
- GNOME 확장을 켜거나 재설치할 필요가 없으며, 알림 기준 목록·설정·예약을 변경하지 않습니다. `api.py`가 같은 디렉터리에 있어야 합니다.
- 요청 실패는 오류로 종료하며 빈 목록으로 표시하지 않습니다. 호출 제한에 걸리면 표시된 대기 시간 이후 다시 실행하세요.

이 스크립트는 **API에 보이는 최근 이력 조회용**입니다. 이것만으로 예약 직후의 실시간 감지까지 보장하지는 않습니다.
새 설치기는 자격 증명을 복사하지 않습니다. 이 별도 스크립트를 처음 사용한다면 직접 준비하세요:

```sh
install -d -m 700 "${XDG_CONFIG_HOME:-$HOME/.config}/pingoose"
install -m 600 uid secret "${XDG_CONFIG_HOME:-$HOME/.config}/pingoose/"
```

원본·기존 개인 설정의 UID/secret은 보존되며 확장 패키지에 포함하지 않습니다.

## 실제 인트라 V3 예약 확인 — 단독 진단

```sh
cd ~/pingoose
/usr/bin/python3 -B intra_evaluations.py
```

전용 창에서 본인 계정으로 로그인하면, 인트라 화면이 받은 실제 평가 API 응답을 읽고 **JSON 출력 후 종료**합니다.
`ok: true`와 `has_upcoming: true`이면 해당 목록에 시작 전 평가가 있습니다. `evaluations`에 역할·프로젝트·시작 시각을 표시합니다.
오류는 `ok: false` 및 종료 코드 1로 구분하며 예약 0건으로 처리하지 않습니다. 기본 대기는 300초이며 `--timeout 600`처럼 늘릴 수 있습니다.

- 시스템 Python의 PyGObject·GTK 3·WebKit2 4.0과 데스크톱 세션이 필요합니다.
- UID/secret, 일반 브라우저의 쿠키, localhost OAuth 콜백 서버를 사용하지 않습니다.
- 별도 비공개 프로필 `~/.local/share/pingoose/intra-check/`에 로그인 세션을 보관합니다(`XDG_DATA_HOME` 존중). 공유하지 마세요.
- **한 번 조회하는 별도 진단 도구**이며 확장·기준 목록을 변경하거나 캠퍼스 전체를 조회하지 않습니다.
- 이 도구의 가짜 API 검사는 통과했습니다. 위에서 설명한 확장 보조 프로세스의 실제 연결 검사와는 별도입니다.

## 다른 API 조회 테스트

`api_get.py`에 **전체 URL이 아닌 `/v2/`부터의 경로**를 넘기면 됩니다. 쿼리의 `&`, `[]`가 셸에서 해석되지 않도록 전체 경로를 따옴표로 감싸세요.

```sh
cd ~/pingoose
python3 -B api_get.py '/v2/campus/69'
python3 -B api_get.py '/v2/users/sanghul2'
python3 -B api_get.py '/v2/scale_teams?filter[campus_id]=69&sort=-begin_at&page[size]=5'
```

기존 개인 설정의 UID/secret으로 앱 토큰을 자동 발급하고, 요청한 경로에 **GET 한 번**을 보냅니다.
등록·수정·삭제 요청이나 사용자 OAuth 로그인은 지원하지 않습니다. 사용자 로그인 또는 별도 역할이 필요한 API는 접근이 제한될 수 있습니다.
외부 서버 URL은 받지 않고 기존 클라이언트의 HTTPS 검증·리디렉션 거부·타임아웃을 그대로 사용합니다.
성공하면 JSON을 출력하고, 실패하면 오류 종류·HTTP 상태·재시도 대기 시간을 stderr에 출력하고 1로 종료합니다.

`uid`, `client_id`, 토큰·secret·password 관련 필드 등 알려진 자격 증명 필드는 중첩된 객체에서도 `[REDACTED]`로 가립니다.
사용 중인 액세스 토큰 문자열도 출력에서 가립니다. **이 도구는 개인정보 전체를 익명화하지 않습니다.** 응답에는 이름·이메일·코멘트 등이 있을 수 있으므로 외부 공유 전에 확인하세요.
일반 조회는 API가 준 JSON 구조와 시각을 유지합니다. 참가자 이름·시간만 간추린 최근 평가를 보려면 `campus_evaluations.py`를 사용하세요.

## 검증과 한계

`./check.sh`는 실제 자격 증명·서비스·로그인 프로필을 사용하지 않습니다.
응답/시간/계정 검증, 첫 기준 목록, 새 ID·중복·재시작·기억 한도, 잘못된 상태 파일 보존을 검사합니다.
확장 보조 프로세스의 GJS/WebKit 검사는 임시 상태 파일과 네트워크 요청이 없는 일회성 프로필을 사용합니다.
별도 진단 도구의 테스트는 로컬 루프백 가짜 서버를 이용합니다.
화면 효과·횟수·DND/잠금·GSettings와 실제 ZIP 허용 목록도 검사합니다. 기존 API/캠퍼스 CLI 회귀 검사도 유지합니다.
그래픽 세션 또는 Node.js가 없어 생략되는 검사는 명시적으로 `SKIP`을 표시합니다.

- 숨긴 실제 보조 프로세스로 본인 계정의 GET을 약 **11.42초 간격으로 두 번** 성공시켰습니다(0건).
  임시 상태 저장, 중복 프로세스 차단, 테스트 명령, EOF 종료도 확인했습니다. 실제 기준 파일·데스크톱 알림은 건드리지 않았습니다.
  **실제 새 예약 → GNOME 수신, 자연스러운 토큰 만료 후 자동 재인증은 아직 별도 확인이 필요합니다.**
- 비어 있지 않은 실제 응답의 모든 필드 형태는 아직 검증하지 못했습니다.
  파서는 실제 프런트의 필드 계약을 기준으로 작성했고, 불일치 시 기준을 유지하며 오류를 표시합니다.
- 이것은 공개 v2 API 앱 인증이 아닌 **실제 인트라 서비스와 로그인 흐름에 연결한 개인 프로토타입**입니다.
  서비스·응답·인증 방식이 바뀌면 수정이 필요합니다. 일반 배포 전에 사이트 정책과 정식 제3자 인증 지원을 확인해야 합니다.
- 처음부터 있던 평가, 두 조회 사이에 생겼다가 사라진 평가, 조회가 끊긴 동안 나타났다 사라진 평가는 알리지 못합니다.
  같은 ID의 시간 변경은 새 예약으로 취급하지 않습니다. ID 저장 직후 종료되면 알림 전달을 놓칠 수 있습니다.
- 이 서비스의 호출 한도와 캠퍼스 일괄 조회 권한은 확인하지 못했습니다. 현재는 **사용자별 조회**입니다.
  전용 웹뷰의 사이트 자체 요청도 있을 수 있습니다. 공유 서버나 캠퍼스 단위 요청 절감은 구현하지 않았습니다.

## 파일

- `extension.js`: GNOME 패널·카드·점멸·비동기 보조 프로세스 통신.
- `webview.js`: 전용 WebKit 로그인, 메모리 인증, 제한된 HTTPS 조회, ID 저장과 프로세스 정리.
- `evaluations.js`: 응답·계정 검증, 중복 제거, 알림 데이터 구성.
- `api.py`, `api_get.py`, `campus_evaluations.py`: 별도 레거시 API 진단/캠퍼스 이력 조회. 확장 ZIP에는 넣지 않습니다.
- `intra_evaluations.py`, `intrapy_check.js`, `intrapy_probe.js`: 별도 일회성 인트라 진단 도구. 확장 ZIP에는 넣지 않습니다.
- `schemas/`, `stylesheet.css`: 기존 설정과 UI 스타일.
- `test-evaluations.js`, `test-flash.js`, `test-api.py`, `test-api-get.py`, `test-campus-evaluations.py`, `test-intra-evaluations.py`, `check.sh`: 회귀 검사.
- `install.sh`: 자격 증명 없는 확장 패키지 설치. 세션 재시작이나 자동 활성화는 하지 않습니다.
