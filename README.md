# Pingoose · 42 Intra Companion

GNOME Shell 42에서 Intra 프로필, 프로젝트, 학습시간, 평가, 아젠다와 알림을 확인하는 확장입니다. 평가 슬롯 관리와 평가 상대 채팅도 제공합니다.

## 설치

42경산 교육용 PC에서 Ubuntu 터미널을 열고, 프로젝트 루트(`install.sh`가 있는 폴더)에서 **sudo 없이** 실행합니다.

```sh
./install.sh
```

GNOME Shell 42, GJS, GTK 3/4, WebKit2 4.0, Soup 2.4, Python 3 GI가 필요합니다. 위 명령은 현재 소스를 패키징해 사용자 확장 경로에 설치합니다. **세션을 자동으로 재시작하지 않으므로**, 설치가 완료되면 아래 순서대로 진행하세요.

1. **GNOME Shell 재시작**
   - X11 환경에서는 `Alt+F2`를 눌러 실행 창을 열고, `r`을 입력한 뒤 `Enter`를 누릅니다.
   - Wayland 환경에서는 로그아웃 후 다시 로그인합니다.

2. **Pingoose 활성화**

   터미널에서 다음 명령을 실행합니다.

   ```bash
   gnome-extensions enable pingoose@local
   ```

3. **인트라 창 열기 및 로그인**
   - 화면 상단 바의 Pingoose 메뉴를 열고 **Log in to 42 Intra**를 누릅니다.
   - 열린 인트라 창에서 로그인이 필요하면 로그인합니다. Intra ID는 현재 PC 사용자명과 같아야 합니다.
   - 이미 로그인되어 있다면 Pingoose 메뉴의 **⋮ → Visit 42 Intra**로 인트라 창을 열 수 있습니다.
   - 로그인 후 Pingoose 메뉴를 다시 열어 프로필과 프로젝트 정보가 표시되는지 확인하세요.

## 동작과 설정

- 로그인은 별도 WebKit 창의 Intra 세션을 사용하며 로그인 계정과 PC 사용자명을 확인합니다.
- 프로필·프로젝트·학습시간·평가·아젠다는 해당 세션으로 조회합니다. 개인 OAuth 앱 키를 입력하는 초기 계획과 현재 구현은 다릅니다.
- General: 색상 모드, Agenda Reset, Logout Intra, Reset All Data. Notifications: 평가·아젠다·채팅 시스템 알림 개별 설정과 화면 점등. 알림을 꺼도 카드와 읽지 않은 메시지는 유지됩니다. Appearance: 각 영역 표시 여부·순서와 패널 위치·간격.
- 메인페이지 ⋮ 메뉴의 Refresh는 프로필·평가·아젠다·학습시간·슬롯 데이터를 다시 요청합니다. 삭제한 아젠다나 평가·알림 카드는 복원하지 않으며, 이미 처리한 알림을 중복 생성하지 않습니다. 갱신 중에는 로딩 아이콘, 완료 시에는 2초 동안 초록색 체크 표시를 보여줍니다.
- 평가 채팅: 평가 카드에서 확인된 상대와 시작 15분 이내에만 연결합니다.
- 채팅은 캠퍼스 좌석 PC 간 TCP 연결을 사용합니다. 계정 인증 기반 메신저가 아니며 상대 PC에서도 호환 수신 기능이 실행 중이어야 합니다.
- Intra 로그아웃 시 대화·입력·연결을 정리합니다.
- 설정은 GSettings, 로그인 및 조회 상태는 사용자 전용 데이터/상태 디렉토리에 저장됩니다. 소스나 배포 ZIP에 인증 데이터를 넣지 마세요.

## 프로젝트 메모

My Projects의 프로젝트를 클릭하면 왼쪽에 프로젝트 제목과 TODO List / Note 탭이 있는 패널이 열립니다. Add Note로 제목과 내용을 입력하고 Save를 누르면 로컬에 저장됩니다. TODO는 한 줄에 할 일 하나를 입력하고 저장 후 체크할 수 있습니다. Edit로 수정하며, 웹페이지는 하단 Visit Project Page로 엽니다.

Settings → Projects는 Appearance 바로 옆에 있습니다. Open project page directly를 켜면 메모 패널 대신 프로젝트 웹뷰를 바로 엽니다. 저장 목록은 생성일 오름차순이며 개별 Delete 및 확인 후 Delete All이 가능합니다. Default project tab에서 Note 또는 TODO List 중 먼저 표시할 탭을 선택합니다.

메모는 `$XDG_STATE_HOME/pingoose/notes/projects.json` (기본 `~/.local/state/pingoose/notes/projects.json`)에 사용자 전용 권한으로 저장됩니다. 프로젝트·로그인 계정별로 구분되며 Intra 로그아웃이나 재로그인으로 삭제하지 않습니다. 저장 전 초안은 현재 실행 중인 확장의 메모리에만 유지되므로 로그아웃·리로드 전에 Save가 필요합니다. 날짜별 알림이나 캘린더 연동은 없으며, TODO에 일정 텍스트를 적는 간단한 관리 기능입니다.

## 42 Services

메인페이지에서 `42 Services`를 열면 서비스 패널이 왼쪽에 표시됩니다. 메모·평가 채팅 등 여러 패널이 열려 있으면 최근에 연 패널이 메인페이지에 가장 가깝게 배치됩니다. ×로 닫기 전에는 메뉴를 다시 열어도 패널 열림 상태를 유지합니다.

- 기본 사이트: SUBAK (`https://subak.site/`), PeerFinder (`https://peerfinder.org/`).
- 기본 이름·URL은 `src/models/settingsDefaults.js`의 `SERVICE_SITES`에서 편집합니다.
- Settings → 42 Services: 기능 활성화, 사이트 추가·수정·삭제, 기본 목록 복원. HTTPS 사이트를 최대 30개 저장합니다.
- Appearance → 42 Services: 버튼·패널 표시 여부. 기능 비활성화 시 열려 있는 서비스 웹뷰도 닫습니다.
- 카드는 공개 공유 이미지 또는 사이트 아이콘을 표시합니다. 이미지를 가져오지 못하면 기본 웹 아이콘을 표시합니다. 미리보기 이미지는 사용자 캐시에 저장됩니다.
- 서비스 창은 기존 Intra WebKit 컨텍스트를 공유합니다. 인증 서버 쿠키를 재사용하되 브라우저의 도메인별 쿠키 규칙을 따릅니다. 최초 서비스 권한 동의나 추가 인증은 사용자가 직접 진행합니다.
- Intra 로그아웃 시 서비스 창을 닫고 공유 웹뷰 데이터를 정리합니다.

## 웹뷰 탐색

웹뷰 앱 이름은 **Pingoose WebView**이며, 창 제목은 현재 웹페이지 제목을 표시합니다. Visit 42 Intra, 서비스 및 프로젝트 웹뷰는 **뒤로 → 앞으로 → 새로고침** 아이콘을 같은 순서로 제공합니다. 이전·다음 방문 기록이 없으면 해당 버튼은 비활성화됩니다.

새로고침 아이콘 또는 **F5**로 현재 페이지를 다시 불러옵니다. 웹페이지 입력란에 포커스가 있어도 F5가 동작하며, 최초 로그인 창에는 탐색 버튼과 F5 단축키를 적용하지 않습니다. 로그인 성공 시 로그인 창은 자동으로 닫힙니다.

설정창의 목록을 갱신하거나 순서를 바꿀 때 기존 스크롤 위치를 보존합니다. 목록이 짧아지면 새 스크롤 범위 안으로 위치를 조정합니다. 이 동작은 높이를 제한한 GTK 목록으로 검증했으며, 환경별 간헐적인 자동 스크롤은 추가 확인이 필요할 수 있습니다.

## 채팅 보호 제한

다음 제한은 평가 상대 채팅의 TCP 통신에 적용됩니다. 평가·아젠다 알림의 수신 빈도에는 적용하지 않습니다.

| 항목 | 제한 | 초과 시 동작 |
| --- | --- | --- |
| 수신 메시지 크기 | 메시지당 4,096바이트 | 해당 연결 종료 |
| 상대별 수신 빈도 | 10초 동안 20개 | 21번째 메시지를 처리하지 않고 해당 연결 종료 |
| 전체 수신 빈도 | 모든 상대 합산 10초 동안 100개 | 한도를 넘긴 메시지의 연결 종료 |
| 시스템 채팅 알림 | 전체 채팅에서 3초에 최대 1번 | 추가 팝업 생략. 메시지와 읽지 않은 수는 유지 |
| 대화 이력 | 상대별 최근 200개 | 오래된 기록부터 삭제. 연결 상태 안내도 포함 |
| 화면 메시지 요소 | 최대 200개 | 오래된 말풍선·상태 안내부터 제거 |
| 동시 연결 | 연결 시도 포함 16개 | 추가 연결 거절 |
| 상대 목록 | 최대 64개 | 새 상대 추가·수신 거절 |
| 전송 대기열 | 상대별 32개 | 추가 전송 요청 거절 |
| 수신 연결 확인 | 최대 15초 | 상대 주소 확인이 끝나지 않으면 종료 |
| 연결 유휴 시간 | 수신 데이터 없이 60초 | 연결 종료. 대화 내역은 유지 |

### 구현 방식과 한계

- 수신 데이터는 1,024바이트 단위로 읽습니다. 줄바꿈까지 누적한 메시지가 4,096바이트를 넘으면 연결을 종료하므로, 긴 데이터를 모두 읽은 뒤 잘라내는 방식이 아닙니다. 바이트 제한은 한글 글자 수와 다릅니다.
- 빈도 제한은 상대별·전체 카운터를 사용하며, 10초가 지난 뒤 다음 메시지를 처리할 때 초기화합니다. 이동 시간창(sliding window) 방식은 아니므로 시간창 경계에서 순간적으로 메시지가 몰릴 수 있습니다.
- 제한 초과에 따른 연결 종료는 영구 차단이 아닙니다. IP별 재접속 속도 제한은 아직 없습니다.
- 시스템 알림은 3초 이내 추가 팝업을 생략합니다. 메시지를 합쳐 나중에 알리는 방식이 아니며, 생략된 알림을 다시 띄우지도 않습니다.
- 60초 유휴 종료는 정상 대화에도 적용됩니다. 다음 메시지를 보낼 때 필요하면 재연결합니다. 이 타이머는 마지막 완성 메시지가 아닌 수신 데이터 기준이므로, 데이터를 조금씩 보내는 연결에 대한 절대 유지시간 제한은 아닙니다.
- 채팅은 일반 TCP입니다. 암호화 및 상대 계정 인증은 아직 없으며, 좌석 주소와 평가 정보 대조만으로 사용자의 신원을 보장하지 않습니다.
- 채팅 알림을 클릭하면 익스텐션과 해당 대화가 열립니다. 평가·아젠다 알림은 익스텐션 메뉴를 엽니다.
- 인증 갱신은 WebKit 세션을 다시 로드해 얻는 토큰으로 처리합니다. 별도 Python 토큰 갱신 파일 및 외부 `session.json` 탐색 경로는 제거했습니다. Intra 로그아웃 시 확장 전용 상태 디렉토리의 `session.json` 등 인증 상태를 삭제합니다. 평가 카드·상대 사진·알림 기록은 직접 삭제하거나 Reset All Data를 실행할 때까지 보존합니다. 과거 다른 경로에 저장된 파일을 찾아 삭제하거나 서버의 토큰을 폐기하는 기능은 아닙니다.

관련 구현: `src/services/chat.js`, `src/ui/chatPanel.js`, `src/ui/notifications.js`, `src/worker/webview.js`.

## 검증 및 배포

프로젝트 루트에서:

```sh
for test in src/tests/*-*.cjs; do node "$test" || exit; done
gjs src/tests/chat-loopback.js
src/scripts/package.sh /tmp/pingoose-release
```

Node 검증은 GNOME UI 일부를 모의 환경에서 검사합니다. GJS 채팅 검증은 로컬 주소로만 연결합니다. 실제 Shell 화면 배치와 다른 PC 사이 통신은 별도로 확인해야 합니다. 패키징 결과에는 실행에 필요한 소스·에셋·설정 스키마가 포함되며, 회귀 테스트와 발표자료는 포함하지 않습니다.

### 설정 초기화와 코드 구조

- Settings → General → Reset All Data: 확인 후 설정을 기본값으로 복원하고, 저장된 노트/TODO, 채팅 내역, 알림, 프로필·이미지 캐시와 웹뷰 로그인 데이터를 삭제하며 Intra에서 로그아웃합니다. 서버의 프로젝트나 평가 슬롯은 변경하지 않습니다.
- 웹뷰 데이터 삭제가 성공하고 웹뷰 프로세스가 종료된 다음 확장 전용 XDG state/cache/data의 `pingoose` 내부 파일을 지웁니다. 심볼릭 링크의 대상은 따라가지 않습니다. 로그아웃 상태 표식과 빈 디렉터리는 유지되며, 웹뷰를 다시 시작할 때 빈 저장소가 생성될 수 있습니다.
- 초기화 기능을 추가한 버전으로 세션을 리로드한 뒤 사용합니다. 확장이 비활성 상태라면 초기화 요청은 다음 활성화 때 처리됩니다. 완료/실패 상태는 General에서 확인합니다.
- `src/prefs.js`는 탭 조립만 담당하고, 기능별 UI는 `src/preferences/{general,appearance,projects,services,layout}.js`, 공통 행·확인창은 `common.js`로 분리했습니다.
- 설정 초기값의 단일 원본은 `src/schemas/org.gnome.shell.extensions.pingoose.gschema.xml`입니다. `src/models/settingsDefaults.js`는 기본 서비스 목록과 스키마 기반 초기화 정책을 담당합니다. 초기값을 중복 선언하지 않습니다.
- 전체 초기화 흐름은 `src/ui/reset.js`, 파일 정리는 `src/services/resetData.js`에 분리했습니다. 개발용 테스트는 임시 XDG 디렉터리와 메모리 설정으로 실행합니다.

Appearance의 섹션 순서는 ↑/↓로 편집한 뒤 Apply를 눌러 저장합니다. 표시 스위치와 하단 Popup Position & Panel Spacing은 즉시 반영됩니다. 기본값은 상단 6px, 좌측 이동 9px, 메인–패널 및 패널–패널 간격 각각 12px이며 간격 0은 맞붙음을 의미합니다.

### 평가 상대 채팅

- 안내는 시작 15분 전이며, 서버 반영을 고려해 실제 요청은 14분 59초 전부터 시작합니다. 상대 정보 확인 여부와 관계없이 시작 직전까지 5초 간격으로 갱신합니다. 최초 좌석 미확인은 Unavailable로 표시합니다. 좌석 확인에 성공한 뒤에는 연속 두 번 미확인일 때 Unavailable로 변경하고 채팅 버튼을 숨깁니다. 확인 정보가 20초 이상 오래된 경우에도 연결을 차단하며, 평가 시작 시각에 상대 조회를 종료합니다. 서버의 Retry-After 제한은 우선합니다. 일반 신규 평가 감시용 조회는 별도로 유지됩니다.
- 평가 시작 15분 전부터 시작 직전까지, 그 구간에 상대의 닉네임과 좌석을 확인하면 평가 카드의 사용자 정보 아래 Cluster Chat 버튼이 나타납니다. 좌석이 확인되지 않으면 버튼을 표시하지 않습니다.
- 클릭하면 상대 좌석을 직접 선택한 채팅 패널을 엽니다. 양쪽의 평가 ID·닉네임·좌석 정보가 일치해야 합니다. 상대도 이 버전의 확장을 사용해야 하며, 기존 평문 채팅 프로토콜과는 호환되지 않습니다.
- 확인한 좌석은 일시적인 조회 실패에도 시작 전까지 유지합니다. 시작 시각부터 송수신을 거절하고, 최대 다음 UI 타이머 주기(약 1초)에 연결·대기 메시지·메모리 기록·채팅 알림을 지웁니다. 평가는 사용자 확인으로 삭제할 때까지 기존 카드에 남습니다.
- 좌석 네트워크·로컬 Intra 평가 정보를 바탕으로 연결을 제한하지만 TCP에는 TLS나 사용자 서명 인증이 없습니다. 수정된 클라이언트에 대한 암호학적 신원 보장은 하지 않습니다.

### 카드 보관
평가 카드와 알림 카드는 직접 삭제할 때까지 로컬에 보관합니다. 알림은 최근 5개 제한 없이 저장하며, ×/Clear All로 삭제합니다. 평가 완료 처리는 평가 카드만 제거하며 알림 카드는 별도로 삭제합니다. 일반 로그아웃은 평가 기록·상대 사진·알림 저장 파일을 보존하고 화면만 숨깁니다. 같은 계정으로 재로그인하거나 세션을 다시 시작하면 복원하며, 복원 자체로 시스템 알림을 다시 발송하지 않습니다. Reset All Data는 이 기록도 삭제합니다. 채팅의 만료·삭제 정책은 변경하지 않습니다.

평가 매칭을 최초 발견한 직후부터 시작 전까지 일반 평가 조회(약 10초 간격, 마지막 15분 구간은 5초 간격)마다 Missing 여부를 검사합니다. 15분 전 좌석 조회가 시작될 때까지 기다리지 않습니다. 정상 응답에서 매칭이 사라지면 카드는 유지하면서 Evaluation Missing 표시와 알림을 추가하고 채팅을 비활성화합니다. 다시 조회되면 표시를 복구합니다. 통신 실패는 Missing으로 판단하지 않습니다. 평가 시작 후에는 마지막 정보로 고정하며, 서버 목록에서 사라져도 Missing으로 변경하지 않습니다.
Missing 카드의 Remove Evaluation은 확인 후 Yes로 삭제하고 Later로 보류합니다. 평가 전용 채팅은 같은 평가 ID와 상대 인트라닉에 한해 좌석이 바뀌어도 대화 기록을 새 연결로 이어갑니다. 좌석 미확인 중에는 송수신을 막고 기록만 메모리에 임시 보관하며, 시작 전 좌석 재확인 시 복원합니다. 평가 시작·매칭 소실·로그아웃·직접 Disconnect 시 해당 기록을 정리합니다. 연결 실패 시 무한 자동 재시도는 하지 않습니다.

좌석 조회에 성공한 후에는 연속 두 번 미확인일 때만 Unavailable로 변경합니다. 그 전에는 마지막 좌석을 유지하며, 새 좌석 확인 성공 시 실패 횟수를 초기화합니다. 채팅 버튼은 유효한 좌석이 확인된 동안만 표시합니다.

### 아젠다 확인과 복원

아젠다 카드의 ⋮ → Delete에서 “Have you checked this agenda?”에 Yes를 선택하면 카드를 숨깁니다. No는 그대로 유지합니다. 삭제한 ID는 GSettings의 `dismissed-agenda-ids`에 저장되므로 일반 Refresh, 자동 갱신, 재로그인, 세션 재시작으로 복원되지 않습니다. 아젠다 하단에는 Refresh 버튼을 두지 않습니다.

Settings → General → Agenda Reset에서 삭제 기록을 초기화하고 현재 서버 아젠다를 다시 요청합니다. 서버에서 이미 사라진 행사는 복원되지 않습니다. 이는 로컬 카드 확인 처리이며 서버 구독 취소나 피드백 제출이 아닙니다.

### 확장 제거와 로그인 데이터

GNOME Shell 42의 확장 제거는 확장 설치 디렉터리와 업데이트 디렉터리만 지웁니다. Pingoose 웹뷰 쿠키는 기본 `~/.local/share/pingoose/cookies.sqlite`, 사이트 데이터는 같은 폴더의 `profile/`, 웹뷰 캐시는 `cache/`에 저장되어 확장 제거 후에도 남습니다. 카드·노트 등 `~/.local/state/pingoose/`와 GSettings도 자동 삭제되지 않습니다. XDG 환경변수를 지정했다면 해당 사용자 경로를 사용합니다.

완전 삭제하려면 확장을 활성화한 상태에서 Settings → General → Reset All Data를 실행하고 완료를 확인한 뒤 GNOME Extensions에서 제거합니다. Reset All Data는 웹뷰 데이터를 지우고 프로세스 종료 후 확장 전용 XDG data/cache/state 파일 및 사용자 설정을 초기화합니다. 단순 비활성화·세션 재시작은 제거와 구별되지 않는 disable 동작을 거치므로 여기에 데이터 자동 삭제를 넣지 않습니다.

### 제출 후 기능 보완

- 슬롯 조회는 시간대가 포함된 날짜 경계를 사용하고 응답 캐시를 사용하지 않습니다. Close All은 클릭 시 다시 조회한 Available 슬롯 전체를 닫고, 삭제 후 남은 슬롯을 검사합니다. 예약된 평가 슬롯은 대상이 아닙니다.
- 슬롯 영역은 다섯 슬롯과 조작 버튼이 보일 수 있도록 확장했으며 제목에 전체 슬롯 개수를 표시합니다. 더 긴 목록은 스크롤합니다.
- 평가 상대의 좌석이 확인되면 평가 ID·상대 로그인·좌석·시작 시각 기준으로 한 번 조용한 연결을 시도합니다. 기존 양방향 hello 검증을 통과해야 카드에 Cluster Chat 버튼이 나타납니다. 실제 메시지·알림·대화창은 생성하지 않습니다. 좌석이 바뀌면 새 좌석을 확인하며, 무응답 상태에서는 자동 재시도하지 않습니다. 현재 평가 채팅의 시작 15분 전~시작 시각 제한은 유지합니다.
- General과 Appearance 사이의 Notifications에서 평가·아젠다·채팅 시스템 알림을 각각 끌 수 있습니다.
